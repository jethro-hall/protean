Protean design system · v0.1 · living reference

One stylesheet. Every page. No drift.

This page is the human-readable mirror of protean-design-system.css. Every swatch and measurement below is read live from that stylesheet at load via getComputedStyle — nothing here is hand-typed, so the guide can never disagree with the code. Change a token in the CSS, reload, and this page updates.

The system is layered so it can be re-themed by touching one layer. Raw colour values (hexes, rgba) live only in Layer 1 primitives. Everything a component references is a role-named Layer 2/3 token. That is Law 2 — nothing hardcoded — expressed as CSS.

The consumer rule. A page or component may use only Layer 2 (semantic) and Layer 3 (scale) tokens and the documented component classes below. Never reach into a Layer 1 primitive (--c-blue-600) and never write a raw hex or px. If you need a value the tokens don't offer, that's a gap — add a token and note it in DESIGN.md, don't inline it.

Colour — semantic tokens

The vocabulary components actually use. Blue is the one system/action colour; orange is the single warm accent (artefacts, subagents) used at most once per view; purple is reserved exclusively for model reasoning in the worklog; green/amber/red are status only.

C11 · (i) info affordance ★ mandatory

Every required input and every produced output carries a small (i). Hidden until hovered, focused or tapped; dismissed with Esc. The content is data — a {what, why, example} hint — never baked into markup. Zero clutter, help on demand (UX §2).

Restated GPiWhatGross profit after the COGS restatement.WhyBooked COGS was polluted by the valuation layer; this anchors cost to paid supplier bills.e.g.$810,843.00 ← shown pinned open (.open) so you can read it; live it appears on hover / focus / tap
Do
  • Attach an (i) to every required field & key output.
  • Keep it hidden until invoked; make it keyboard-reachable.
Don't
  • Leave help text always-on — that's clutter.
  • Put essential info only in the tooltip.

C12 · Truthful state banners ★

Loading, degraded, error and empty all render honestly. A spinner must never sit on top of a failure (UX §1).

Building a new page

The whole contract in one place.

<!-- 1. Link the system. Nothing else styles the page. --> <link rel="stylesheet" href="protean-design-system.css"> /* 2. Compose with documented classes + Layer 2/3 tokens ONLY */ .my-panel { padding: var(--s-6); background: var(--surface); border: 1px solid var(--line); border-radius: var(--r); box-shadow: var(--shadow-sm); } /* ✗ never: padding:14px; background:#fff; color:#4C8DD6; */
Do
  • Reuse a component class if one fits.
  • Add any genuinely new page-only class in a namespaced block.
  • Need a missing value? Add a token + a DESIGN.md note.
Don't
  • Write a raw hex, rgba or px anywhere in a page.
  • Fork the system's CSS to tweak one screen.
  • Touch Layers 1–3 without the governance note / ADR.
