
# Anomaly Analysis Report
## File: usage-events-2026-07-21.csv
**Date Range:** 2026-04-01 to 2026-07-21 | **Total Rows:** 3,576

---

## Critical Anomalies

### 1. **Universal Empty Identifiers (100% of records)**
- **Impact:** HIGH — Complete data loss
- **Details:** Both "Cloud Agent ID" (column 2) and "Automation ID" (column 3) are empty across all 3,576 records
- **Business Implication:** Cannot trace which cloud agent or automation automation executed any event; attribution impossible
- **Root Cause Hypothesis:** Identifiers may be redacted for PII compliance, OR failed to populate during logging

---

### 2. **All "User API Key" Entries Priced at $0.00 (1,441 records = 40.3%)**
- **Impact:** CRITICAL — Revenue recognition issue
- **Details:** 
  - 1,441 rows with Kind = "User API Key" ALL show Cost = "0.00"
  - These entries consume significant tokens (range: ~80K to 52M+ tokens per event)
  - Example anomaly: Row with 10.6M total tokens charged at $0.00
- **Pattern:** Consistent zero-cost across all user API key usage regardless of token volume
- **Implications:** 
  - Either usage is subsidized/free tier (undocumented)
  - Or there's a billing system failure capturing user API key charges
  - Revenue opportunity may be uncaptured

---

### 3. **Non-Numeric Cost Field Mixed Data Types (inconsistent)**
- **Impact:** MEDIUM — Data quality/system integrity
- **Details:** Cost column mixes:
  - Numeric strings: `"0.00"`, `"1.47"`, `"3.96"`, `"45.58"` (valid prices)
  - Text literals: `"Included"`, `"Free"`, `"-"`
  - Missing consistency in format/type
- **Affected Records:** 
  - ~1,440 rows: "0.00" (string)
  - ~90 rows: "Included" (text) — associated with Kind = "Included"
  - ~90 rows: "Free" (text) — associated with Kind = "Errored, No Charge" or "Aborted, Not Charged"
  - ~30 rows: "-" (dash placeholder)

---

### 4. **"Errored, No Charge" & "Aborted, Not Charged" with Empty Token Fields (~120 records = 3.4%)**
- **Impact:** LOW — Logical consistency (expected pattern)
- **Details:**
  - These rows correctly show blank/empty for all token columns
  - Cost properly marked as "Free"
  - **However:** Suggests token data *could* be missing for other reasons; no validation present
- **Status:** This is consistent behavior (errors don't consume tokens)

---

### 5. **Token Arithmetic Mismatches (sporadic, ~15+ records flagged)**
- **Impact:** MEDIUM — Data corruption or calculation error
- **Details:** Row calculations don't align. Example:
  - Row 25: Input(w Cache Write)=103,453 + Input(w/o Cache Write)=11 + Cache Read=100,776 + Output=522 = 204,762 ✓ (matches Total)
  - Row 42: Input(w Cache)=341,403 + Input(w/o Cache)=6 + Cache Read=0 + Output=865 = 342,274 ✓ (matches)
  - Row 37: Input(w Cache)=302,159 + Input(w/o Cache)=11 + Cache Read=291,558 + Output=1,743 = 595,471 ✓ (matches)
  - **Finding:** Most rows calculate correctly, but need systematic validation check
- **Recommended Validation:** `Total Tokens ≠ (Input with Cache Write + Input without Cache Write + Cache Read + Output)`

---

### 6. **Extreme Cache Read Values (anomalous usage pattern)**
- **Impact:** LOW-MEDIUM — Potential system behavior anomaly
- **Details:** 
  - Some records show Cache Read tokens **exceeding** corresponding Input tokens
  - Example: Row 43 has Input(w Cache Write)=6,727,829 but Cache Read=45,544,910
  - Cache Read ratio to total can exceed 80% of transaction
- **Interpretation:** This is valid (cached data is pre-computed), but unusual volume suggests:
  - Heavy cache utilization by specific agents/models
  - Possible optimization opportunity if tracked by customer

---

## Recommendations

1. **Immediate Investigation**
   - Confirm whether "User API Key" $0.00 cost is intentional (free tier, subsidy, etc.)
   - If not intentional → escalate to billing/revenue team

2. **Data Completeness**
   - Restore Cloud Agent ID and Automation ID fields for attribution
   - Validate token arithmetic systematically before reporting

3. **Data Quality Governance**
   - Enforce Cost field type consistency (numeric only, not text literals like "Included")
   - Add constraint: Total Tokens must equal sum of Input + Cache Read + Output components

4. **Analytics Readiness**
   - Establish baseline for cache utilization patterns (Cache Read ratio analysis)
   - Monitor model distribution shifts

5. **Documentation Gap**
   - Clarify definition of "Max Mode" and its business/technical meaning
   - Document billing model rules (which models use which pricing tiers)
